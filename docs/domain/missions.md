# Domain — 미션 기준과 상태 판정

코드 상의 단일 기준은 [`src/lib/missions.ts`](../../src/lib/missions.ts) 다. 이 문서와 코드가 다르면 코드를 기준으로 하고 이 문서를 고친다. 원본 기준은 사용자가 준 "Passage 베타테스트 최종 미션 표" 와 SQL `beta_mission_check.sql` (2026-10-31, 저장소에 없음). 이전 튜토리얼 PDF 기준(받은 피드백 확인 · 유용해요 · 최종 설문 등)은 이것으로 대체했다 ([D-006](../DECISIONS.md#d-006)).

## 구분별 목표

| 미션 | 일반인 | 실력자 | 전문가 |
| --- | --- | --- | --- |
| 최초 녹음 업로드 | 2 | 2 | - |
| 일반 게시글 코멘트 | - | 5 | 7 |
| 재연습 업로드 | 1 | 1 | - |
| 재연습 글 코멘트 | - | - | 3 |
| 총 미션 | 3 | 8 | 10 |

구분은 Passage `profiles.role` (`user` · `skilled` · `expert`).

## 세는 기준 (DB 함수 `monitor_mission_status`)

- 최초 녹음 = 본인 글 중 재연습이 아닌 글 / 재연습 = `is_repractice` 인 글 (같은 곡 두 번째 이후)
- 코멘트 = 남의 글에 단 피드백만, 글 단위 (한 글에 여러 개 달아도 1개). 대상 글이 재연습이면 재연습 글 코멘트
- 지워진 글 · 피드백은 세지 않음. 운영자 · 테스트 계정 제외 (`monitor_excluded_accounts` 표)
- 집계 시작일을 고르면 그날(한국 시간 0시) 이후만 센다

## 진행률 · 상태

- 진행률 = Σ min(실적, 목표) / 총 미션. 목표를 넘긴 개수는 넣지 않는다. 예: 실력자 녹음 2 · 코멘트 3 · 재연습 0 → 5/8 = 63%.
- 완료: 목표 전부 채움 / 진행 중: 목표 미션 실적이 하나라도 있음 / 미활동: 없음.
- 화면 순서: 구분 → 미완료 먼저 → 진행률 낮은 순 → 닉네임(글자 코드 순). 엑셀 순서: 구분 → 진행률 높은 순 → 닉네임.
